Open an issue on GitHub

Reporting a bug

A useful report lets someone reproduce the problem without guessing. Please include the browser and version, your operating system, the tool you were using, and the exact steps that led to the issue. Describe what you expected and what happened instead. If the page showed an error message, quote its text.

  • Say whether the problem happened with video, an image or an SRT file.
  • Use a small sample file when possible; never upload private or confidential footage.
  • Mention if the file played correctly in another application.
  • Note the platform selection if the safe-area guide looked wrong.

Requesting a feature

Feature requests work best when they describe the creator problem first and the proposed solution second. For example, a useful request explains which subtitle convention is hard to check today and what warning would help, rather than only naming a new button. Because the site deliberately avoids external services, requests that need a server or paid API are unlikely to be adopted.

Privacy questions

Because no files, text or account details are collected, there is no personal record to look up or delete. The privacy policy explains local processing and hosting-level network logs. If you believe a page behaves differently from that description, open an issue and describe the observation.

Response expectations

Issues are reviewed on a best-effort basis. There is no paid support plan, service-level agreement or guaranteed reply time. Clear, reproducible reports are the fastest to act on, and duplicates can be linked together to keep discussion in one place.

Staying independent

ClipCheck Studio is not affiliated with TikTok, Instagram or YouTube. Feedback is used to improve the toolkit, not to represent any of those platforms. Platform names on the site are labels for common formats, and guidance may change as those formats change.
